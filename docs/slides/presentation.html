Open Source Speech-to-Text

OpenTranscribe

5 STT models. Real-time streaming. Zero API keys.

Why This Exists

  • Cloud transcription services charge per minute and lock you into their API
  • No single open-source model wins every use case (speed, accuracy, offline)
  • Comparing models requires painful manual setup of each engine separately
  • Real-time streaming and file-based transcription rarely live in the same tool

OpenTranscribe wraps 5 free models behind one interface, runs locally, and lets you compare them head-to-head.

Request Flow: File Transcription

  1. Upload: User drops audio/video file in the browser UI
  2. Authenticate: Next.js API route validates session cookie
  3. Proxy: Next.js forwards the file to FastAPI on localhost:8000
  4. Detect: FastAPI checks if it's video; extracts audio if needed
  5. Transcribe: Selected STT model processes the audio
  6. Respond: Text, segments, timestamps, language returned as JSON

WebSocket Streaming Protocol

Client sends

  • {type: "start"}
  • {type: "audio", data: base64}
  • {type: "stop"}

Server responds

  • {type: "ready"}
  • {type: "partial"}
  • {type: "final"}
  • {type: "vad"}

Two endpoints: /ws/transcribe/stream (Vosk, lightweight) and /ws/live/stream (Faster Whisper + Silero VAD, higher accuracy).

Faster Whisper (Default)

  • CTranslate2 reimplementation of OpenAI Whisper
  • 4x faster inference with equivalent accuracy
  • GPU acceleration via CUDA when available
  • Used for both file transcription and live streaming
  • Silero VAD integration for voice activity detection
# Factory pattern with decorator @register_model("faster-whisper") class FasterWhisperTranscriber: def transcribe(self, path, lang): model = WhisperModel("base") segments, info = model.transcribe( path, language=lang ) return TranscriptionResult(...)

Vosk: Lightweight Streaming

  • Kaldi-based, only ~50MB model download
  • No GPU required, runs on any hardware
  • Best for real-time embedded use cases
  • Supports push-to-talk, toggle, and VAD recording modes
  • Multiple output modes: display, auto-save, clipboard

Speaker Diarization

  • Powered by pyannote.audio 3.1
  • Combines STT output with speaker segmentation
  • Supports configurable speaker count (1-20)
  • Each segment tagged with speaker identity
  • Graceful fallback if pyannote not installed
# Midpoint matching algorithm for segment in transcription.segments: seg_mid = (segment.start + segment.end) / 2 for turn, _, label in diarization: if turn.start <= seg_mid <= turn.end: speaker = label break
